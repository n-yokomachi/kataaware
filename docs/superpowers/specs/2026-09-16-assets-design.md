# 舞台と小物のモデル 設計（場面 1）

- 作成日: 2026-09-16
- 対象: 要素「舞台と小物のモデル」。場面 1（自室）の仮の箱を、PS1 風の描画と実際のモデルに置き換える
- 前提: `2026-09-15-game-design.md`（素材の方針）、`2026-09-15-foundation-design.md`（舞台の読み込み口）、`2026-09-16-scenario-design.md`（自室に置く物）
- 位置づけ: 実装時点の意思決定記録。場面 2 以降の舞台は、その場面を追加する段で本書に節を足す

## 1. 決定事項

- 見た目: PS1 風。画面の 3 分の 1 程度の解像度で描いて最近傍で拡大し、ディザと色数の削減を後処理で載せる。頂点の揺れは試してから入れるか決める
- 素材の系統: 一般的な物（机、椅子、卓、ドア、棚）は Kenney の Furniture Kit（CC0、glTF 配布）を第一候補にし、足りない物は KayKit で補う。固有物（メモリハブ、端末、灰皿、煙草の箱、前腕とジャック）は Hunyuan3D をローカルで動かして形状だけ生成し、色は材質で付ける。ローカルの環境構築でつまずいたら、固有物だけ Tripo で生成する
- 配置: 「どの glTF を、どの位置・向き・大きさで置くか」を並べた配置データを TypeScript で持ち、GLTFLoader で読む。three.js editor の書き出し（1 ファイルに全部を埋め込む）は使わない。微調整用に `?layout` の確認モードを設ける
- 当たり判定: 置いた物の外接箱から自動で取り、飾りは `collider: false`、必要なら見えない壁を足す（基盤の設計書 5 節のまま）
- この段で扱わないもの: 端末の画面に映る顔の反射と片割れの顔（次の段）、煙の見た目（今の重ね表示のまま）、音、起動後の端末の文面の表示

## 2. PS1 風の描画

- `Fx` の描画先を低解像度にする。EffectComposer に、画面の `1/3` の大きさで `NearestFilter` の描画先を渡し、合成の最後の出力で画面いっぱいに拡大する。解像度の比は 1 か所の定数で持つ
- 後処理の順: 描画（低解像度）→ 眩暈 → 色味 → 減色とディザ → 出力。減色は各チャンネル 32 段階、ディザは 4×4 の規則的なパターン。強さは数値で持ち、0 で素通しになる
- 頂点の揺れ（PS1 の位置精度の粗さ）は材質のシェーダに手を入れる方法で試し、酔いや読みづらさが出なければ入れる。入れる場合も数値で強さを持ち、0 で止められる
- 字幕、印、中央の文字は HTML なので粗くならない。3D だけが粗くなる
- 眩暈のぼかしは低解像度の上で掛かるので半径の数値を見直す

## 3. 配置データと読み込み

- `EnvironmentDef` を `{ boxes?: BoxDef[]; layout?: LayoutItem[]; url?: string }` に広げ、仮の箱と配置データを 1 つの舞台に混在させられるようにする。段階的な置き換えのため
- `LayoutItem`: `asset`（`public/assets/` 以下の glTF の相対パス）、`position`、`rotationY`（ラジアン）、`scale`（省略時 1）、`collider`（省略時 true）、`tint`（省略時なし。材質の色を上書きする）
- 読み込みは GLTFLoader。同じ `asset` は 1 度だけ読み、置くたびに複製する。外接箱は置いた後の world 座標で計算して当たり判定にする
- `?layout` モード: 画面上の物をクリックで選び、移動と Y 回転を操作して、変更後の `LayoutItem` をコンソールに書き出す。書き出した値を配置データに手で写す。通常の遊びには影響しない
- 素材は `public/assets/<系統名>/` に置き、`public/assets/LICENSES.md` に出典と許諾を記録する

## 4. 素材の調達

- Kenney Furniture Kit をダウンロードし、自室に要る物の glTF だけを `public/assets/kenney/` に入れる。無い物は KayKit の同種のパックで補う
- 固有物は Hunyuan3D 2.1 の形状生成で作る。入力は文章か参考画像。出力は三角形数を 3,000 以下に減らして GLB にする（`gltf-transform` の簡略化）。テクスチャ生成は使わず、部位ごとに単色の材質を当てる
- 生成する固有物と要点:
  - メモリハブ: 16 枚挿しのラック。前面にスロットが並ぶ箱
  - 端末: 物理モニターと薄いキーボード。画面は黒い板
  - 灰皿: 吸い殻が乗った皿
  - 煙草の箱: 紙巻き煙草の紙箱。『双鶴』の意匠は素材の段では入れない
  - 前腕とジャック: 手首の内側にジャックが刺さった前腕。抜いた後の状態（ジャックとケーブルなし）も要る
- Hunyuan3D はこの端末（RTX 4070 12GB、RAM 32GB）に導入する。形状生成だけなので軽量モデルかメモリ退避で足りる。導入手順は計画に含め、大きなダウンロードの前にオーナーに確認する

## 5. 前腕とジャック

- 前腕はカメラの子として付け、下を向いたとき（ピッチが一定より下）だけ表示する。主観に手を描かない方針の例外
- ジャックを抜くと、ケーブルつきの前腕からケーブルなしの前腕に切り替える。抜く動作の見た目は作らない

## 6. 段階

1. 描画と配置の仕組み: PS1 風の後処理、配置データと GLTFLoader、`?layout` モード。今の仮の箱を粗い描画で出し、配置データの読み込みは 1 つの試験用 glTF で確かめる
2. Kenney の物への差し替え: 自室の一般的な物を配置データに置き換える。仮の箱は固有物の位置だけ残す
3. 固有物の生成と差し替え: Hunyuan3D の導入、5 点の生成と減量、前腕の表示の仕組み、差し替え

段ごとに計画を書き、通しで遊べる状態を保ったまま進める。

## 7. 検証

- 単体: 配置データから外接箱を求める処理、減色とディザの数値の扱い（0 で素通し）
- 目視: in-app ブラウザで `?nolock&debug` と `window.__step` を使い、3D は `#view` の取り出しで見る。見た目の最終判断はオーナーが通常のブラウザで行う
- 各段の終わりに、場面 1 を最初から最後まで通して遊べることを確かめる
