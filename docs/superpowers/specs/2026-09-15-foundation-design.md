# 基盤の実装 設計

- 作成日: 2026-09-15
- 対象: 要素「基盤の実装」。文章も素材も仮のまま、場面 1（自室・導入）を遊べる状態を作る。場面 2 以降は、その場面を追加する段で仕組みごと足していく
- 前提: `2026-09-15-game-design.md` の場面構成と体験の型に従う
- 位置づけ: 実装時点の意思決定記録

## 1. 完了条件

- ブラウザで「クリックで開始」から始め、自室でチップ・端末・ドアの順に調べると暗転して「続く」の表示まで到達できる
- 歩く、見回す、調べる、字幕、印、暗転、眩暈の後処理、導入のクレジットとタイトルが仮の箱の舞台で動く
- 場面の進行、当たり判定、調べる対象の選択、字幕の送りは描画から切り離した関数になっていて、vitest が通る
- `vite build` の出力を静的サーバに置いて動く

## 2. 技術構成

- three.js、Vite、TypeScript、vitest。版は実装時点の最新安定版に固定する（設計時点では three 0.186 / Vite 8 / TypeScript 7 / vitest 5）
- 物理エンジン、ナビメッシュ、UI ライブラリは使わない

```
src/
  main.ts          起動。開始画面 → App
  core/
    app.ts         レンダラ、時計、ループ、後処理の組み立て
    input.ts       キー状態、ポインタロック、マウス移動量
    scene-manager.ts  現在の場面、転換（カット／暗転）、進行の状態機械
    walk.ts        歩行。位置、向き、当たり判定の呼び出し
    collide.ts     箱同士の判定と壁沿いの滑り（純粋関数）
    interact.ts    調べる対象の選択（純粋関数）と実行
  scenes/
    index.ts       場面固有の演出の一覧
    runtime.ts     場面 1 つ分の実行
    environment.ts 仮の箱と外部ファイルから舞台を組む
    hooks/*.ts     場面固有の演出（この段は導入のクレジットとタイトルのみ）
  data/
    scenes/*.ts    場面データ。調べる対象、字幕、必須（この段は自室のみ）
  ui/
    overlay.ts     HTML の重ね表示。字幕、印、クレジット、タイトル、開始画面
    subtitles.ts   字幕の待ち行列と送り（純粋関数＋DOM 反映）
  fx/
    daze-pass.ts   ぼかしと輪郭の揺れ。数値で制御する自作パス
    tone-pass.ts   場面ごとの色味
```

## 3. 実行時の構造

- `App` がレンダラ、カメラ、EffectComposer、ループを持つ。ループは `SceneManager.update(dt)` → 後処理の描画の順
- `SceneManager` は現在の場面を 1 つ持ち、`enter` / `update` / `exit` を呼ぶ。転換はカット（即時）と暗転（黒へのフェード）の 2 種
- 場面は `kind` を持つ。この段で実装するのは `walk`（歩行）だけで、`rail`（受け身）と `car`（視線移動と調べる操作のみ）は該当する場面を追加する段で足す
- 進行は状態機械で管理する。`walk` は必須の対象をすべて調べると次へ。次の場面が無ければ暗転して「続く」を表示する

## 4. 場面データ

場面の中身は TypeScript のデータとして定義し、シナリオの段で文章だけ差し替えられるようにする。

- 共通: `id`、`kind`、`next`、`transition`（`cut` | `fade`）、`tone`（色味）、`environment`（仮の箱の一覧。後の段で glTF や書き出した場面ファイルに置き換える）
- `walk`: `spawn`（位置と向き）、`colliders`（見えない壁。省略時は舞台の物から自動生成）、`interactables`（`id`、位置、半径、`required`、`after`（先に済ませる対象）、字幕の行、`once`）、`onEnter` の字幕、`dazeOnEnter`（入ったときの眩暈）、`seat`（座った状態で始め、`standAfter` の対象を調べると立ち上がる）。`interactables` の `hints` は `after` の id ごとの未達時の文で、文がある id は未達でも選べて文だけ出る。`dazeOnEnter.until` はその対象を調べるまで眩暈を保つ
- `rail` のデータ（経路、体の数値、見回しの範囲、時刻つきの演出）は記憶シーンを追加する段で定義する

## 5. 歩行と当たり判定

- 見回しは Pointer Lock API のマウス移動量から自前で計算する。後で足す受け身の記憶シーンでも同じ仕組みを使う。移動は WASD。走る操作は入れない
- プレイヤーは軸に沿った箱として扱う。舞台の静的な物の外接箱を集めて判定の一覧にし、必要なら見えない壁の箱を場面データで追加する
- 移動は X と Z を別々に試し、ぶつかった軸だけ止めて壁沿いに滑らせる。高低差は扱わない
- `collide.ts` は「移動前の位置、移動量、箱の一覧」から「移動後の位置」を返す純粋関数にする

## 6. 受け身の記憶シーン（後続の段で実装する設計案）

- 経路は点列から作る曲線で、時間から位置を求める。向きは曲線の進行方向を基準にし、マウスの見回しを `lookLimit` の範囲に収める
- `body` の数値は次のように反映する。目線の高さはカメラの Y のずらし、ぼかしは眩暈パスの強さ、速さは経路の再生倍率、揺れは位置に加える正弦波の振幅
- 経路の時間が尽きると `next` へ進む。記憶 2 と庭の記憶の後は自室へ戻り、戻った直後に眩暈の演出を出す
- `rail.ts` は「経路、時刻、マウスの角度、体の数値」から「位置、向き」を返す純粋関数にする

## 7. 調べる操作

- 画面中央からのレイキャストと距離の両方で対象を選ぶ。距離内かつ視線の角度内の対象のうち最も近いものに印を出す
- E キーまたはクリックで実行し、その対象の字幕を流す。`required` の対象は実行済みとして記録し、進行の判定に使う
- `interact.ts` の選択部分は「カメラの位置と向き、対象の一覧」から「選ばれた対象」を返す純粋関数にする

## 8. UI

- HTML の重ね表示で作る。字幕は画面下、印は画面中央、クレジットとタイトルは中央、開始画面は全面の黒に「クリックで開始」
- 字幕は待ち行列で管理し、E キーまたはクリックで次の行へ送る。行が尽きたら消える
- 字幕の表示中は E キーとクリックを字幕の送りにだけ使い、調べる操作は受け付けない
- 場面 1 の冒頭はぼかしの中でクレジットとタイトルを順に出し、視界の回復に合わせて消す
- 結末は最後の字幕、暗転、タイトルの順。この段では次の場面が無いので、ドアを出た後に暗転して「続く」を出す

## 9. 後処理

- EffectComposer に RenderPass → 眩暈パス → 色味パス → 出力の順で並べる
- 眩暈パスは、ぼかしの半径と、UV を正弦波で揺らす振幅と周波数を数値で持つ自作のシェーダ
- 色味パスは、指定色への寄せ具合を数値で持つ
- 数値は場面データと演出のイベントから時間で補間して変える。仮の箱の段では見え方の調整はせず、数値で動くことだけを確認する

## 10. 舞台の作り方

- この段では場面データに書いた仮の箱だけで舞台を組む
- 後の素材の段では、自室・ヤード・庭は公式の three.js editor で置いて書き出した場面ファイルを読み、ネオンの通りと小路は規格化した部品を格子状のデータで並べ、固有の小物は AI 生成の glTF を読む。麦畑は 1 本の低ポリを大量複製する。この置き換えができるよう、`environment` の読み込み口は仮の箱と外部ファイルの両方を受けられる形にしておく

## 11. 検証

- vitest で先にテストを書く対象: 進行の判定、当たり判定と滑り、調べる対象の選択、字幕の待ち行列、歩行の向きと移動
- 目視で確認する対象: 自室の通し、操作感、暗転、後処理。in-app ブラウザで行う
- 完了時に `vite build` の出力を静的サーバで起動して通しを再確認する

## 12. ビルド

- Vite の `base` を `./` にし、相対パスで動く静的ファイルを出力する
- 出力を zip にして itch.io に置く。zip の作成手順は投稿の段で決める

## 13. この段で扱わないもの

- 場面 2 以降と、そのための仕組み（受け身の経路、車内、モンタージュ）
- 本物の素材、確定した文章、音の再生、片割れの顔

## 14. 場面 2 に入る前に決めること（実装後の持ち越し）

- 調べる対象の選択に遮蔽判定（壁越しに選べない）を入れるか。閉じた自室では不要だったが、露店や車内では要る
- 眩暈パスの揺れの周波数を数値化するか。受け身シーンで体ごとに変えるなら要る
- `Input.justPressed` と `Runtime.time` は未使用。受け身シーンで使うか削るか
- `Runtime` / `SceneManager` / `Fx` の減衰にはテストが無い（純粋関数のみテスト済み）
- ビルドは three 込みの単一 chunk 約 680 kB（gzip 約 170 kB）。投稿段で許容するか判断
- ポインタロックあり（`?nolock` 無し）の通常ブラウザでの 1 周は AI 側の環境では確認できない。オーナーの手元で確認する
- `Overlay` に煙を止める手段が無く、場面の終了で煙が消えない。場面 2 を足す前に `cancelSmoke` を用意して `onExit` から呼ぶ
- `Runtime.freeze` は上書きなので、長い停止の途中に短い停止を呼ぶと短くなる。複数のフックが呼ぶようになったら最大値を取る
- `Runtime.update` は字幕の反映がフックの `onUpdate` より先なので、フックから出した文は 1 フレーム遅れて表示される
- ジャックには仮の箱が無く、印だけが空中に出る。素材の段まで仮の箱を置くか判断する
